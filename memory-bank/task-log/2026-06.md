백엔드와 프론트엔드를 변경된 `youtubeUrl` API 계약에 맞게 수정했다.

### 고려한 대안

- 문서만 변경하고 코드는 다음 단계로 미룬다.
- 백엔드 DTO만 먼저 변경한다.
- 백엔드 DTO, 더미 API, 프론트엔드 입력 UI를 함께 변경한다.

### 최종 결정

백엔드와 프론트엔드의 요청 계약을 동시에 `youtubeUrl` 기준으로 맞추고, 자막 추출과 OpenAI 연동은 다음 단계로 분리한다.

### 결정 이유

API 계약과 화면 입력 방식은 서로 직접 연결되어 있으므로 한쪽만 변경하면 다음 작업에서 혼란이 생긴다. 반면 자막 추출과 OpenAI 연동은 별도 기술 결정이 필요하므로 더미 응답 단계에서 계약을 먼저 고정하는 것이 안전하다.

### 영향 범위

- `SummarizeRequest`는 `youtubeUrl`만 받는다.
- 프론트엔드 요청 body는 `{ "youtubeUrl": "..." }` 형식이다.
- 유효하지 않은 유튜브 URL은 프론트엔드와 백엔드에서 모두 차단한다.
- 백엔드는 Vite 로컬 개발 서버의 CORS 요청을 허용한다.

### 후속 작업

유튜브 자막 추출 방식을 결정하고 `YouTubeTranscriptService`를 구현한다.

### 작업

YouTube 자막 추출 방식을 비공식 공개 자막 추출 방식으로 결정했다.

### 고려한 대안

- 공식 YouTube Data API Captions API를 사용한다.
- 비공식 공개 자막 추출 방식을 사용한다.
- 외부 Transcript API/SaaS를 사용한다.

### 최종 결정

MVP v1에서는 비공식 공개 자막 추출 방식을 사용한다.

### 결정 이유

공식 YouTube Captions API는 자막 다운로드에 OAuth 및 영상 소유권/권한 제약이 있어, 사용자가 임의의 공개 유튜브 URL을 입력하는 현재 MVP 목표와 맞지 않는다. 외부 Transcript API는 빠르게 구현할 수 있지만 추가 비용과 외부 서비스 의존성이 생긴다. MVP v1은 학습 및 빠른 배포가 목적이므로 공개 자막이 있는 영상만 지원하는 비공식 추출 방식을 우선 적용한다.

### 영향 범위

- 공개 자막 또는 자동 자막이 있는 영상만 요약할 수 있다.
- 자막이 없거나 YouTube 응답 구조가 변경된 경우 실패할 수 있다.
- 실패 시 `이 영상의 자막을 가져올 수 없습니다.` 메시지를 반환한다.
- 운영 안정성이 필요해지는 다음 버전에서는 외부 Transcript API 또는 공식 API 기반 구조를 재검토한다.

### 후속 작업

`YouTubeTranscriptService`를 구현하고 `SummaryService`에 연결한다.

- 모든 후속 작업은 테스트/빌드와 Memory Bank 업데이트 후 커밋 및 push까지 수행한다.
- 커밋 전 `git status`로 변경 범위를 확인한다.
- push 실패 시 원인과 현재 상태를 Memory Bank와 최종 응답에 기록한다.
